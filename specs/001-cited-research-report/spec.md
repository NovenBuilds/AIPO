# Feature Specification: 带引用的商机研究报告

**Feature Branch**: `cursor/remaining-acceptance-94b4`

**Created**: 2026-11-13

**Status**: Draft

**Input**: User description: "继续首版交付。真实调用方用一句话调用已有研究入口；服务用已配置的真实模型规划关键词和来源、选择值得深读的样本，并依据证据生成带引用的中文商机报告。同一问题验收小红书和闲鱼，并继续核对其他已登记来源。验收还要覆盖服务重启恢复、部分来源失败，以及挂牌价与成交证据的区分。回放不得登记为实采。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一句话得到有出处的报告 (Priority: P1)

调用方只提交一句话。服务自己规划该看哪些已登记来源、用哪些关键词，挑出值得深读的样本，并交出一份可读的中文商机报告。报告里的事实能回到本次证据。

**Why this priority**: 这是首版的主路径。没有它，调用方仍要自己操作多个平台。

**Independent Test**: 用一句话发起研究，取得任务编号，看到进度，并读到带证据编号的中文报告。未配置模型时，程序仍根据已归档证据写出报告，且不把这次写成模型已参与。

**Acceptance Scenarios**:

1. **Given** 研究服务已启动，**When** 调用方提交一句话，**Then** 返回任务编号和初始状态，调用方不需要再调用各平台工具。
2. **Given** 已配置可用模型，**When** 研究执行，**Then** 关键词和来源选择、深读样本选择、报告判断都来自该模型，并且每条事实引用本次证据编号。
3. **Given** 模型未配置、超时或引用了不存在的证据，**When** 研究执行，**Then** 任务仍可依据已归档证据定稿，并记下模型结果未被采用。
4. **Given** 同一次请求使用相同的重试编号和相同参数，**When** 再次提交，**Then** 复用原任务；参数不同则返回可解释的冲突。

---

### User Story 2 - 同一问题看小红书和闲鱼，并核对其他来源 (Priority: P2)

同一个问题同时看小红书讨论、正文、评论和闲鱼商品。其他已登记来源按各自已有能力做搜索、补读或导入。每条来源留下版本、实际读取深度和证据。

**Why this priority**: 首版范围是全部已登记来源，小红书和闲鱼是核心实采路径。

**Independent Test**: 用优先看小红书和闲鱼的同一句话跑完。能连通的来源留下真实读取深度；不能连通的来源保持未连通、缺命令或未登录，不用样例填结果。

**Acceptance Scenarios**:

1. **Given** 小红书服务已登录，**When** 执行该问题，**Then** 报告同时有讨论或评论，以及实际读到的正文深度。
2. **Given** 闲鱼命令已授权，**When** 执行该问题，**Then** 先确认登录，再搜索商品并读取详情；挂牌价单独记录。
3. **Given** 某个来源没有安装、没有登录或没有可导入文件，**When** 执行，**Then** 该来源记为真实阻塞，其他来源的结果仍然保留。
4. **Given** 一次研究使用了回放夹具，**When** 查看登记，**Then** 登记为回放，不记为实采。

---

### User Story 3 - 中断、部分失败和价格边界 (Priority: P3)

研究可能在进程重启、单个来源失败或只有标价没有成交时结束。调用方仍能按原任务编号继续，并分清挂牌价和成交证据。

**Why this priority**: 没有这些边界，部分成功会被写成完整结论，挂牌价会被写成已经成交。

**Independent Test**: 在第一条来源归档后停住并换进程恢复；让一个来源超时而另一个成功；准备一条只有挂牌价的商品和一条带平台状态或独立核验成交字样的材料，检查报告没有把它们写成同一种价格。

**Acceptance Scenarios**:

1. **Given** 进程在定稿前退出，**When** 用原任务编号继续，**Then** 已完成来源不重复取证，研究可以定稿。
2. **Given** 一个来源超时或失败，**When** 其他来源已有证据，**Then** 报告保留成功证据，并写明失败来源不能补进结论。
3. **Given** 证据里只有挂牌价，**When** 生成报告，**Then** 报告称其为挂牌或咨询标价，并写明没有独立核验成交。
4. **Given** 证据里有平台状态或卖家自述，**When** 生成报告，**Then** 它们与挂牌价、独立核验成交分开表述。

### Edge Cases

- 模型新增了未登记来源，或删掉了用户已经点名的平台：忽略越界部分，保留程序允许的来源。
- 模型选出的深读编号不在本次候选里：不深读该编号，改用程序的默认深读上限。
- 搜索有卡片但详情失败：保留搜索卡片，不把详情写成已读。
- 闲鱼登录状态无法确认：不搜索商品。
- 空结果：记为空结果，不把它写成尚未查询。
- 样本不足：报告可以完成，但必须留下结论缺口，并且不并列多个收费方向。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 服务必须接受一句话并返回任务编号，调用方通过查看和继续两个动作跟踪同一次研究。
- **FR-002**: 已配置模型时，服务必须让模型提出关键词和来源，再由程序限制在本次问题允许的已登记来源和采样预算内。
- **FR-003**: 已配置模型时，服务必须让模型从本次搜索候选中选择深读样本，深读数量不得超过已有预算。
- **FR-004**: 报告必须是中文，包含研究问题、实际来源与覆盖、目标客户、支持证据、反例、价格与成本假设、最小付费验证、停止条件和结论缺口。
- **FR-005**: 报告中的事实引用必须指向本次归档证据。引用不存在的编号时不得定稿该模型稿。
- **FR-006**: 未配置模型或模型稿被拒绝时，服务必须仍根据已归档证据给出报告。
- **FR-007**: 同一问题在小红书和闲鱼都可用时，报告必须同时包含讨论侧和商品供给侧，并且两边不能合成一个成交故事。
- **FR-008**: 每个来源必须记录状态、登记类别、版本或版本未知、读取深度和阻塞原因。
- **FR-009**: 回放、导入和实采必须分开登记。回放夹具不得在实采失败时填补结果。
- **FR-010**: 进程重启后必须能按原任务编号恢复，已写入的批次保持可引用。
- **FR-011**: 部分来源失败时，其他来源的证据必须保留，失败来源不得被其他平台样本假装补齐。
- **FR-012**: 挂牌价、卖家自述、平台公开标记和独立核验成交必须分开。没有独立核验时，报告必须写明没有成交证据。
- **FR-013**: 登录、命令或配置缺失时，服务必须留下真实原因，不得改为成功。

### Key Entities

- **研究任务**: 一句话、任务编号、状态、计划、归档位置和模式。
- **来源进度**: 来源、平台、能力、状态、登记、版本、读取深度、尝试次数和阻塞原因。
- **证据**: 稳定编号、平台、链接、材料类型、读取深度和原件引用。
- **价格观察**: 挂牌价、卖家自述、平台公开标记或独立核验成交。四类不能互相替代。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 调用方只提交一句话，就能拿到任务编号、进度和一份可阅读的中文报告。
- **SC-002**: 配置了可用模型时，同一次研究的关键词、深读选择和判断文字都能追溯到该模型的输出，并且判断中的证据编号全部属于本次归档。
- **SC-003**: 小红书和闲鱼各自要么留下真实读取深度，要么留下具体阻塞原因；其他已登记来源也有对应的搜索、补读、导入或阻塞记录。
- **SC-004**: 重启后的任务编号不变，已完成来源的取证次数不增加。
- **SC-005**: 只有挂牌价的材料不会在报告里变成成交价；平台状态和卖家自述也不会被写成独立核验成交。
- **SC-006**: 回放结果的登记始终是回放，实采失败不会出现回放夹具里的样例标题。

## Assumptions

- 首版工具名、来源清单、采样上限和归档编号规则已经确定，本次只补齐模型参与和验收缺口。
- 模型使用调用方已经配置的兼容接口。本环境没有密钥时，记录缺口，不用另一个未配置的服务代替。
- 小红书和闲鱼的实采依赖运行环境里的登录或授权。没有这些输入时不缩小首版范围，但也不能把回放写成实采。
- 闲鱼详情接口里的标价字段表示挂牌，不表示已经成交。
- 用户点名的平台必须保留。模型只能在程序已经允许的来源里取舍，不能添加未登记来源。
- MediaCrawler 继续只导入，不启动爬虫。
