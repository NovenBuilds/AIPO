# 模型配置

模型负责规划关键词和来源、选择值得深读的样本，并写出带引用的中文判断。程序负责任务、预算、超时、归档和引用校验。没有模型时，服务仍会根据已归档证据写出中文报告。

## 配置项

写在配置的 `model` 对象里，或用环境变量覆盖：

| 项 | 环境变量 | 含义 |
| --- | --- | --- |
| `base_url` | `AIPO_MODEL_BASE_URL` | OpenAI 兼容接口的根地址，以 `/chat/completions` 结尾前的那一段 |
| `name` | `AIPO_MODEL_NAME` | 模型名 |
| `api_key_env` | 无 | 读取密钥的环境变量名，默认 `AIPO_MODEL_API_KEY` |
| `timeout_seconds` | 无 | 单次补充的超时秒数 |

密钥只放在环境变量里。配置文件里出现 `api_key`、`token`、`cookie`、`password` 会被拒绝。

仓库根目录的 `.env.example` 只列出变量名，不含密钥。

## 程序会检查什么

已配置模型时，服务按顺序做三件事：

1. 规划。模型给出最多 3 个关键词，以及要保留的已选来源。程序丢掉未登记来源，并保留用户在问题里点名的平台。不合法时沿用程序计划，事件记 `model_plan_rejected`。
2. 深读。实采时，模型只能从本次搜索候选里选择编号。小红书最多 6 篇，闲鱼最多 5 件。编号不可用时按预算默认深读，事件记 `model_select_rejected`。回放不把这一步套到夹具上。
3. 判断。模型文字必须包含目标客户、反例、挂牌、成交、最小付费验证和停止条件。每个 `[E…]` 编号都必须是本次归档里的证据编号，不能出现证据和问题里都没有的数字，也不能写“登记”或把任务写成实采。完整且合法时，这段判断替换程序简报中机会判断到结论缺口之前的部分，事件记 `model_report`。只通过引用、但段落不完整时，作为“模型补充”附在后面。不符合时丢掉草稿，事件记 `model_rejected`。

程序简报始终能独立成文，包含：研究问题、来源与覆盖、机会判断、目标客户、支持证据、反例、交叉证据、价格与成本假设、最小付费验证、结论缺口、证据一览。挂牌价、卖家自述、平台公开标记和独立核验成交分开写。定稿时旧归档程序还会附上实际渠道状态和证据索引，并拒绝不存在的编号。

采样预算沿用平台共同规则的上限：最多 30 篇、深读 6 篇、评论索引每篇 20 条、商品 5 条。首版每个来源只发一次搜索，避免三组关键词叠在一起超过上限。实际读了多少，以来源行里的读取深度为准。
