# 服务启动

研究服务是常驻进程。调用方只连接这一个 MCP（模型上下文协议）入口，不自己调用小红书、闲鱼或其他平台工具。

## 首次配置

1. 在仓库根目录复制示例配置：

```bash
cp configs/aipo.example.json configs/aipo.local.json
```

2. 示例配置的 `mode` 是 `replay`（回放）。回放会跑通流程，但报告会写明「本任务没有实采结果」。有对应平台权限时，再把 `mode` 改成 `live`（实采）。`auto` 与 `live` 相同，失败不会用回放夹具填补。
3. `projects` 里的 `path` 指向本机上游副本，相对路径相对仓库根目录。这些目录在根目录 `.gitignore` 的 `/upstream/` 中，不要把上游源码提交进本仓库。
4. 小红书沿用现有只读地址 `http://127.0.0.1:18060`。闲鱼沿用本机已经能用的 `goofish` 命令，不自动改用 Docker 沙箱。
5. 导入材料写在 `imports`，值是导出文件的路径。没有文件就不会编造导入结果。

`configs/aipo.local.json` 已被忽略。不要把 Cookie、令牌或模型密钥写进配置。

## 启动

在仓库根目录：

```bash
python3 -m aipo serve
```

宿主里的 MCP 配置示例：

```json
{
  "mcpServers": {
    "aipo": {
      "command": "python3",
      "args": ["-m", "aipo", "serve"],
      "cwd": "/绝对路径/本仓库",
      "env": {"AIPO_CONFIG": "configs/aipo.local.json"}
    }
  }
}
```

协议走标准输入输出。客户端用换行分隔的 JSON 时，服务按同样方式回答；客户端用 `Content-Length` 头时，服务按同样的头回答。日志不要写到标准输出。

三个工具：

| 工具 | 作用 |
| --- | --- |
| `start_research` | 传入 `question`，可选 `request_id`、`platforms`。返回任务编号和初始状态「等待」。相同重试编号和相同参数复用原任务；参数冲突会返回说明。 |
| `get_research` | 查看状态、阶段、各来源进度。定稿后文本里包含中文报告。 |
| `resume_research` | 按原任务编号继续。登录或依赖恢复后把补充说明放进 `answer`。已完成批次保留。 |

任务状态：等待、执行中、等待用户、已完成、失败。来源状态沿用旧归档契约里的代码，例如 `success`、`empty`、`need_login`、`timeout`，中文原因写在同一行。

不通过 MCP 时，也可以在仓库根目录同步跑完一条：

```bash
python3 -m aipo start --sync --question "你的问题"
python3 -m aipo get --id r任务编号
python3 -m aipo resume --sync --id r任务编号 --answer "已重新登录"
```

诊断只读，不安装、不登录、不搜索：

```bash
python3 -m aipo doctor
python3 -m aipo doctor --probe
python3 -m aipo fingerprint
python3 -m aipo map
```

`--probe` 会访问配置里的小红书健康检查和登录状态接口。默认诊断不联网。

## 测试

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest tests.test_aipo -v
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s legacy/topic-signal-radar/tests -v
```

第二行是迁入基线的离线测试，必须保持通过。它不证明平台已登录。
