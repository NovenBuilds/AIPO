# 给 Grok Bot 的开发交接

## 任务与授权范围

把已有 AIPO 话题信号雷达和商机研究技能重组为一个可直接生成报告的研究服务。一句话进，中文报告出。对外提供一个 MCP（模型上下文协议）服务，对内复用已有 MCP、命令行工具和数据导入。按 [平台矩阵](平台与依赖.md) 做**多平台首版**。小红书和闲鱼是核心实采路径，国内外其他登记来源及导入按其已有能力一起纳入首版。

这个仓库以原项目提交 `d0b4a550e58e9ff4f00a20e6410b54833cc81891` 和当前技能文件为迁入基线。[历史材料索引](../legacy/README.md) 记录了原始来源。仓库含可运行的归档/诊断代码及历史测试。服务实现从 [架构与契约](架构与契约.md) 开始。使用宿主已有授权的模型和来源配置，本机采样结果与脱敏回放分开交付。

## 开发任务

1. **复用已有路径。** 用依赖清单定位八个上游，核对实际版本、入口和输入输出，画出平台与能力的对应关系。优先复用小红书与闲鱼现有配置。版本未知的下载副本通过文件指纹对照，记录实际使用版本和补丁。
2. **建立统一研究流程。** 实现工具入口、后台任务状态、按能力选来源、统一证据、检查点与超时恢复。沿用现有归档语义和历史证据编号的可读性。来源适配使用同一返回契约，现成上游继续负责抓取或导出。
3. **完成首版全部登记来源。** 小红书、闲鱼、国内外近期检索、原文补读、评论补充与已有导入可并行实现和验收。按平台登记可用能力及真实失败原因。用于单接口开发的样本回放是同一交付的验证方式。
4. **形成可独立运行的交付。** 完成服务启动说明、可复用测试、首次配置示例和模型配置项说明。将旧商机技能接成该服务的快捷入口，写出原入口切换和回退步骤。记录已完成任务、可复验记录及余项，下一轮从最近的检查点接续。

## 交付验收

| 验收 | 完成标准 |
| --- | --- |
| 一句话到报告 | 智能体通过真实 MCP 连接提交问题、取得任务编号、查看进度、拿到可读报告；调用方无需自己调用多个平台工具。 |
| 多平台 | 同一任务结合小红书的讨论与评论和闲鱼的商品观察。国内外其他来源按能力分别走通搜索、补读或导入。公开索引与站内结果分别标注。 |
| 失败与恢复 | 通过回放验证空结果、会话失效、部分来源超时、重复提交、进程重启。可按原任务编号恢复，已完成批次仍可引用。 |
| 商机判断 | 报告列目标客户、证据与反例、挂牌价或费用假设、最小付费验证。无充分样本时保留结论缺口；可从引用回到原始证据。 |
| 实测交付 | 留存实际使用的来源、版本、时间和读取深度。小红书和闲鱼分别在有相应权限的环境复验。其他来源逐项注明实采、仅回放、导入或受阻。 |

可从 [跨平台回放样例](回放样例.json) 开始，其中小红书示例保留实际响应的主要结构，闲鱼示例定义标准化目标。中文检索另有历史测试样本，见旧雷达测试目录。

首个完整问题可以用「我会开发微信小程序，每周能投入 5 小时，帮我找一个值得试着收钱的方向，优先看小红书和闲鱼」。用其覆盖讨论、供给、价格、验证计划与交叉证据。随后用国内外对照、指定平台、单来源失败和证据不足用例覆盖其他路径。
